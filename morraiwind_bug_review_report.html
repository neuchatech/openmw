Executive Summary

Most likely crash cause: empty victim used before validation in creature melee hits

Severity: critical Confidence: high Commit: da5b356846 Path: apps/openmw/mwclass/creature.cpp

Creature::hit now calculates hit chance before checking whether victim is empty. If a creature attack animation reaches its hit key while no target was actually contacted, getHitChance dereferences the empty victim. This exactly fits an intermittent crash while enemies start or finish attacks.

Second crash path: ranged hits now notify Lua even without a valid actor victim

Severity: critical Confidence: high Commit: da5b356846 Path: apps/openmw/mwmechanics/combat.cpp

projectileHit moved LuaManager::onHit outside the validVictim block. LuaManager::onHit sends a local event to victim, and sendLocalEvent calls getId(victim), which calls victim.getCellRef(). An empty projectile target can therefore crash deterministically.

Most likely black map cause: local map RTT was not updated for the new fog shader contract

Severity: high Confidence: high Commit: 259c8b66fd / 668d1add5a Paths: localmap.cpp, fog.glsl, renderingmanager.cpp

The local map render-to-texture pass still disables only old fixed-function/old shader fog uniforms. The new fog shader ignores that path and reads fogStart, fogEnd, fogColor, exponentialFogDensity, heightFogEnabled, cameraPos, and invViewMatrix. Those are inherited from the gameplay camera, not the map camera. A re-rendered map segment can be fogged or sky-blended into black/dark output.

Crash Findings

1. Creature::hit dereferences empty victim

apps/openmw/mwclass/creature.cpp:286-295

In upstream, hit applied fatigue loss, then returned immediately if victim.isEmpty(). The Dec 19 rewrite moved hit-chance calculation above that guard. getHitChance reads victim.getClass().getCreatureStats(victim), so the empty-victim case crashes before the intended guard.

@@ Creature::hit(...)
         MWWorld::Ptr weapon;
         ...
-        MWMechanics::applyFatigueLoss(ptr, weapon, attackStrength);
+
+        // Sprint 7: Calculate hit chance for damage scaling
+        float attackerSkill = ptr.get<ESM::Creature>()->mBase->mData.mCombat;
+        float hitchance = MWMechanics::getHitChance(ptr, victim, static_cast<int>(attackerSkill));

         if (victim.isEmpty())
             return; // Didn't hit anything

Annotation: the guard is now too late. getHitChance dereferences victim.
Likely runtime path: CharacterController::prepareHit calls evaluateHit; if no contact exists, mAttackVictim remains empty but the attack animation can still reach the hit key and call charClass.hit. This is intermittent because it depends on animation timing, target movement, reach, and collision.

Fix direction: Move if (victim.isEmpty()) return; above getHitChance. Also make getHitChance robust by returning a safe default when either attacker or victim is empty or non-actor.

2. projectileHit sends a Lua Hit event for empty/non-actor victims

apps/openmw/mwmechanics/combat.cpp:326-339 and apps/openmw/mwlua/luamanagerimp.cpp:557

Before the rewrite, the Lua hit notification for projectiles was inside if (validVictim). It is now unconditional. When a projectile hits terrain, water, or any no-target case, this can pass an empty victim to Lua local event dispatch.

@@ projectileHit(...)
-        if (validVictim)
-        {
-            ...
-            MWBase::Environment::get().getLuaManager()->onHit(attacker, victim, weapon, projectile, ...);
-        }
+        MWBase::Environment::get().getLuaManager()->onHit(attacker, victim, weapon, projectile, 0,
+            attackStrength, damage, true, hitPosition, true, MWMechanics::DamageSourceType::Ranged);

@@ LuaManager::onHit(...)
         sendLocalEvent(victim, "Hit", data);

@@ getId(...)
         return ptr.getCellRef().getRefNum();

Annotation: empty victim reaches getCellRef().

Fix direction: Restore the upstream invariant: only call onHit for valid actor victims. If Lua needs miss/world-impact events later, create a separate event that does not require a local script target.

3. Staged projectile guard is incomplete and can itself crash

apps/openmw/mwworld/projectilemanager.cpp:532-537

The staged working-tree change tries to avoid empty caster crashes, but it calls target.getClass() without checking target.isEmpty().

-            if (caster.isEmpty())
+            if (caster.isEmpty() && target.getClass().isActor())
                 caster = target;

Annotation: this must be `!target.isEmpty() && target.getClass().isActor()`.

Fix direction: Change to if (caster.isEmpty() && !target.isEmpty() && target.getClass().isActor()). Then audit the rest of ProjectileManager::processHits, because magic bolt handling still uses caster.getCell() without an empty check.

4. getHitChance staged guard covers attacker only, not victim

apps/openmw/mwmechanics/combat.cpp:345-357

The staged change adds an attacker guard, but victim.getClass() remains unconditional. That does not protect the Creature::hit crash.

+        if (attacker.isEmpty() || !attacker.getClass().isActor())
            return 100.0f;

         MWMechanics::CreatureStats& victimStats = victim.getClass().getCreatureStats(victim);

Annotation: victim needs the same kind of guard.

5. Tests do not currently prove the stamina shield implementation

apps/openmw_tests/mwmechanics/testcreaturestats.cpp and apps/openmw/mwmechanics/creaturestats.cpp:174-179

The test claims 40 melee damage drains 40 fatigue and leaves health unchanged. The implementation uses factor = 5.0f * fatigueMult, so 40 damage with 100 fatigue absorbs 100 fatigue and still deals 20 health damage. Either the test is stale or the implementation factor is wrong.

Map Findings

1. Local map RTT still disables old fog, but the shaders now use new uniforms

apps/openmw/mwrender/localmap.cpp:739-749, files/shaders/compatibility/fog.glsl:1-14

The local map renderer comments say shader fog does not respect disabled GL_FOG, so it overrides old uniforms. After the fog rework, that is no longer enough.

@@ LocalMapRenderToTexture::setDefaults(...)
         // assign large value to effectively turn off fog
         // shaders don't respect glDisable(GL_FOG)
         osg::ref_ptr<osg::Fog> fog(new osg::Fog);
         fog->setStart(10000000);
         fog->setEnd(10000000);
         stateset->setAttributeAndModes(fog, osg::StateAttribute::OFF | osg::StateAttribute::OVERRIDE);

         // turn of sky blending
         stateset->addUniform(new osg::Uniform("far", 10000000.0f));
         stateset->addUniform(new osg::Uniform("skyBlendingStart", 8000000.0f));
         stateset->addUniform(new osg::Uniform("screenRes", osg::Vec2f{ 1, 1 }));

@@ fog.glsl after fog rework
+uniform float exponentialFogDensity;
+uniform bool heightFogEnabled;
+uniform float heightFogDensity;
+uniform float heightFogFalloff;
+uniform float heightFogOffset;
+uniform vec3 cameraPos;
+uniform mat4 invViewMatrix;
+uniform float fogStart;
+uniform float fogEnd;
+uniform vec4 fogColor;

Annotation: local map overrides none of the new fog controls.

Why this makes black maps plausible: local map segments are generated by a top-down RTT camera, but the new height fog uses cameraPos and invViewMatrix from the gameplay camera. If the global fog color is black/dark, or if inherited uniforms are still at defaults, re-rendered segments can collapse toward black. Exploration updates trigger exactly these segment/fog texture updates.

Fix direction: In LocalMapRenderToTexture::setDefaults, override the new uniforms for the map camera. The simplest safe fix is to disable shader fog for the RTT pass: huge fogStart/fogEnd, exponentialFogDensity = 0, heightFogEnabled = false, and explicit fogColor. Consider doing the same in characterpreview.cpp, which has the same old skyBlendingStart override pattern.

2. Forced shaders and new defaults make the local map hit the risky path by default

files/settings-default.cfg

The graphics commits changed default settings to high-distance, shader-heavy rendering: force shaders = true, radial fog = true, exponential fog = true, height fog = true, sky blending = true, distant terrain = true, and viewing distance = 122880. These make the local map render through the new fog shader instead of the old fixed-function behavior.

3. Shader include path edits in bs/*.frag are suspicious

files/shaders/compatibility/bs/default.frag and files/shaders/compatibility/bs/nolighting.frag

The fog commit changed includes like #include "compatibility/vertexcolors.glsl" to #include "vertexcolors.glsl" from files inside compatibility/bs/. If the shader preprocessor resolves includes relative to the including file, this can fail or pick the wrong file. It is less directly tied to the black map symptom than the local-map fog uniform gap, but worth verifying in the shader log.

Suggested Fix Order

  1. Crash stopgap: guard Creature::hit before getHitChance, and make getHitChance reject empty/non-actor attacker or victim.
  2. Projectile stopgap: put projectile Lua onHit back inside validVictim, and repair the staged target.getClass() guard.
  3. Map fix: update LocalMapRenderToTexture::setDefaults to override all new fog uniforms for the RTT camera, or provide a shader define/pass flag that disables fog for map/preview RTTs.
  4. Validation: add regression tests for Creature::hit with empty victim, projectileHit with empty victim, and local map RTT state containing the new fog uniforms.
  5. Cleanup: reconcile stamina shield tests with implementation, then run formatting/whitespace checks.

Implementation Appendix

Crash fixes applied

  • Creature::hit and Npc::hit now reject empty/non-actor victims before hit chance, stats, reach, Lua, or damage logic.
  • getHitChance, elemental shields, hand-to-hand damage, block checks, melee reach helpers, normal-weapon resistance, and werewolf damage now reject invalid pointers before dereferencing actor/weapon data.
  • projectileHit now keeps ranged Lua Hit events inside the valid actor-victim path, skips projectile inventory recovery for empty projectiles, and uses explicit valid-attacker/valid-victim booleans.
  • ProjectileManager now guards empty targets before target.getClass(), guards active magic bolts before caster.getCell(), relaxes debug assertions for empty saved/restored casters, and rejects empty magic-bolt casters at launch.
  • CastSpell now avoids launching bolts or playing cast effects with an empty caster.

Map fog fix applied

LocalMapRenderToTexture and CharacterPreview now install explicit override uniforms for the new fog shader contract: near, far, skyBlendingStart, screenRes, exponentialFogDensity, height fog fields, cameraPos, invViewMatrix, fogStart, fogEnd, and fogColor. The RTT passes still disable legacy osg::Fog, but no longer rely on that alone.
