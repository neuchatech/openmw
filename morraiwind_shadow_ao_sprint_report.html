Shadow Pipeline

OpenMW shadows are driven by scene masks and an OSG shadow technique. The sprint keeps that contract intact: the renderer decides which categories may cast, the shadow manager creates shadow maps, and receiver shaders sample shadowTexture0..N with existing uniform layout.

Mask Split In Plain Terms

Before this sprint, exterior object shadows = true pulled in both ordinary objects and paged static exterior chunks. In dense cities that means the shadow pass may traverse and draw large amounts of world geometry. Now nearby active-grid paged statics count as object casters, while far/merged paged statics remain independent: 

[Shadows]
object shadows = true
static object shadows = false

This preserves useful nearby rock/clutter/object shadows while keeping heavy distant static city geometry out of the default shadow caster set.

Stable CSM

The new path computes cascades from the camera frustum, fits each cascade to a stable bounding volume, builds a directional-light orthographic projection, and snaps the light-space center to the shadow map texel grid. The goal is less shadow swimming while rotating or moving the camera.

Selectable Fallback

[Shadows]
shadow mapping method = stable csm

# fallback:
# shadow mapping method = legacy vdsm

Stable CSM currently reuses the existing shadow texture/uniform contract. That keeps shader churn low and lets the legacy path remain as a direct fallback if the prototype shows visual issues in specific scenes.

Contact AO

Contact AO is intentionally small and practical. It uses postprocess depth, normals, world position, and a short sample pattern to darken tight contact areas near the camera. It should help ground clutter, actor feet, rocks, crates, barrels, steps, and building-ground contact lines without asking every static object to cast real-time shadows. 

[Shadows]
enable ambient occlusion = true
ao method = contact
ao radius = 90.0
ao strength = 0.65
ao sample count = 8
ao fade distance = 4096

PowerShell Commands

Operational note: run compiles from PowerShell yourself. Avoid launching OpenMW CMake/Ninja builds through Codex/WSL, because Windows/WSL may retain build memory until the shell or WSL VM is restarted.

Run these from a regular PowerShell prompt on Windows. The commands assume the repo is at D:\data\code\openmw.

Preflight

Set-Location D:\data\code\openmw
git branch --show-current
git status --short

Try A Fresh Build

Set-Location D:\data\code\openmw
& "C:\Program Files\CMake\bin\cmake.exe" --build .\MSVC2022_64_Ninja --config RelWithDebInfo --target openmw --parallel 6

Fast Incremental Builds

# Launcher UI only
cmd /c "call MSVC2022_64_Ninja\ActivateMSVC.bat && cmake --build MSVC2022_64_Ninja --parallel --config Release --target openmw-launcher"

# Game executable only
cmd /c "call MSVC2022_64_Ninja\ActivateMSVC.bat && cmake --build MSVC2022_64_Ninja --parallel --config Release --target openmw"

# Existing repo helper, now targeted to game + launcher instead of the full all target
.\fastcompile.bat

If that configuration does not produce RelWithDebInfo\openmw.exe, build Release instead: 

& "C:\Program Files\CMake\bin\cmake.exe" --build .\MSVC2022_64_Ninja --config Release --target openmw --parallel 6

If Build Stops On Bullet

Select-String -Path .\MSVC2022_64_Ninja\CMakeCache.txt -Pattern "OPENMW_USE_SYSTEM_BULLET|BULLET_INCLUDE_DIR|BULLET.*LIBRARY|BT_USE_DOUBLE"

Send the output if it still says Bullet is not double precision. The shadow code did not reach compile during my full build attempt because CMake stopped at that dependency check.

Combat Stall Investigation

Current read: the direct hit-registration path is bounded. The likely failure mode is a hit-triggered phase change that fans out into AI/pathfinding, Lua hit handlers, or transient combat VFX. Spell particles and VFX use Mask_Effect/Mask_ParticleSystem, while the new shadow caster mask does not include those masks, so VFX should not become shadow casters directly.

Added Runtime Counters

F4/resource stats and OSG stats now include free world effects, projectile counts, combat engagement checks, siding-cache misses, forced flee, path builds, pathgrid fallbacks, navigator failures, and cumulative path build milliseconds.

Most Useful First Test

Reproduce save 77 once with stats capture. If AI Path Build ms, AI Navigator Failures, or AI Combat ForceFlee jumps when the stall starts, the culprit is likely AI/pathfinding. If Rendering Free Effects, Projectiles MagicBolts, Lua memory, or resource caches climb, focus on VFX/Lua/resource churn.

Risks And Review Points

Area Risk What To Check
Stable CSM fit First runtime build may show cascade coverage, clipping, or precision issues. Rotate slowly, look toward/away from the sun, inspect terrain and actor shadows at split boundaries.
Shader compatibility Contact AO and stable shadow sampling need real GLSL compile coverage on the target renderer. Check openmw.log for shader compile errors and toggle AO on/off.
Performance attribution Cascade cull logs are CPU-side; OSG stats provide broader render/cull/GPU frame timing. Use both enable shadow cascade stats and OPENMW_OSG_STATS_FILE.
Dependency state The current CMake cache points at a Bullet setup that fails the double-precision requirement. Resolve Bullet/reconfigure before trusting runtime results from an older executable.
